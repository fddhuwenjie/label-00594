# 自测报告

## 硬性门槛说明

本系统采用 Docker Compose 一键部署方案，执行 `docker compose up -d` 命令即可完成全部服务启动。系统包含三个容器服务：PostgreSQL 数据库服务（purchase-approval-db）、ASP.NET Core 后端 API 服务（purchase-approval-api）以及 Nginx 前端服务（purchase-approval-web）。启动完成后，前端界面通过 http://localhost:3000 访问，后端 API 通过 http://localhost:5001 访问，Swagger 接口文档通过 http://localhost:5001/swagger 访问。后端服务启动时会在控制台输出明确的 "Startup Success" 成功标志及访问地址信息。

## 交付完整性说明

系统完整实现了需求文档中定义的全部功能模块。用户管理模块支持多角色登录（员工、经理、财务、总经理、管理员）及角色权限控制。采购申请模块实现了申请的创建、编辑、提交、撤回、查询等全生命周期管理。审批工作流模块基于 WorkflowCore 引擎实现了三级金额分级审批（5000/20000 分界），支持同意、拒绝、退回三种审批操作。通知中心实现了审批状态变更的实时消息推送。仪表盘模块提供了待审批数量、申请统计、采购金额、通过率等多维度数据展示。

## 工程与架构质量说明

后端采用 ASP.NET Core 8 框架，遵循清晰的分层架构设计，包括 Controllers 控制层、Services 业务逻辑层、Models 数据模型层、Data 数据访问层和 Workflows 工作流层。数据持久化使用 Entity Framework Core 8 配合 PostgreSQL 16 数据库，工作流引擎选用成熟的 WorkflowCore 3.10。前端采用 React 18 + TypeScript 5 技术栈，使用 Vite 5 作为构建工具，Zustand 进行状态管理，UI 组件库选用 Ant Design 5。整体架构清晰，职责分明，便于维护和扩展。

## 工程细节与专业度说明

系统在工程细节方面体现了较高的专业水准。后端 API 使用 RESTful 风格设计，通过 HTTP Header（X-User-Id）传递用户身份信息，所有接口均有完善的参数校验和异常处理。数据库层面使用了唯一索引（申请编号、用户名）确保数据一致性，采用了 EF Core 的导航属性实现关联查询。工作流定义使用了 WaitFor 事件驱动模式和条件分支，实现了灵活的审批流程控制。前端实现了路由守卫、全局错误拦截、Token 自动携带等标准化处理。容器化部署配置了健康检查和依赖启动顺序。

## Prompt 需求理解与适配度说明

系统准确理解并实现了用户提出的"基于 WorkflowCore 框架开发采购审批管理项目"的核心需求。WorkflowCore 引擎被用于实现采购审批的多级流程控制，而非简单的状态机实现。审批规则严格按照金额分级（5000/20000）触发不同级别的审批链路。系统提供了完整的测试数据覆盖所有审批状态（草稿、待审批、各级已批、已通过、已拒绝、已退回、已撤销），便于验证各种业务场景。界面设计遵循了用户指定的科技蓝主色调和商务风格。

## 美观度说明

前端界面严格遵循设计规范文档，采用科技蓝（#1677FF）作为主色调，浅灰（#F0F2F5）作为背景色，呈现现代化商务风格。页面布局采用 Ant Design 的 Layout 组件，左侧固定导航栏、顶部用户信息栏、主内容区响应式布局。所有表单、表格、卡片组件统一使用 8px 圆角，配合适当的阴影效果增强层次感。状态标签使用语义化配色（蓝色待处理、绿色通过、红色拒绝），数据图表使用 @ant-design/charts 实现柱状图和折线图可视化。整体视觉效果统一协调，符合企业级管理后台的专业标准。
